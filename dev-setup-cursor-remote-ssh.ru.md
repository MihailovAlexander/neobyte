# Настройка окружения разработчика: Cursor Remote SSH + MCP

**Версия:** 0.5 · **Дата:** 2026-09-11  
**Статус:** черновик (дополняется по ходу настройки сервера)  
**Для кого:** разработчики и аналитики 1С (пилот, до 5 человек)  

Документ описывает, что нужно сделать **на своём ПК**, чтобы работать с общим Ubuntu-сервером через Cursor (Remote SSH). Настройки **сервера** здесь не дублируются подробно - их делает администратор хаба.


## 1. Новый SSH-ключ: создать и прислать публичную часть

Без вашего публичного ключа администратор не сможет выдать доступ на сервер. Сгенерируйте **новую** пару ключей на своём Windows-ПК, затем пришлите **только публичную** часть.

**Приватный** ключ никуда не отправляйте: он остаётся только у вас.

### 1.1. Создать ключ

1. Откройте PowerShell.
2. Сгенерируйте ключ типа Ed25519:

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.ssh"
ssh-keygen -t ed25519 -C "vashe.imya@company.com"
```

В `-C` укажите своё имя или рабочую почту — так ключ проще узнать в списке.

3. На вопросы `ssh-keygen`:
   - **путь к файлу** — нажмите Enter, если подходит значение по умолчанию (`C:\Users\ВАШ_USER\.ssh\id_ed25519`);
   - **passphrase** — можно задать (тогда SSH / Cursor будут спрашивать её) или оставить пустой (два раза Enter).

Если команда спрашивает, **перезаписать** уже существующий `id_ed25519` — отвечайте **n**. Задайте другое имя, например:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519_neobyte" -C "vashe.imya@company.com"
```

Тогда в пункте 2 в `IdentityFile` укажите этот же файл (`~/.ssh/id_ed25519_neobyte`), а не `id_ed25519`.

### 1.2. Что получилось на диске

| Файл | Это | Куда |
|------|-----|------|
| `id_ed25519` (без `.pub`) | **Приватный** ключ | Только ваш ПК. Никому не присылать, не копировать в чат, не класть в git |
| `id_ed25519.pub` | **Публичный** ключ | Этот файл (или его содержимое) прислать администратору |

Путь по умолчанию: `C:\Users\ВАШ_USER\.ssh\`.

### 1.3. Показать публичный ключ

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

Если ключ назвали иначе:

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519_neobyte.pub"
```

Строка выглядит так (одна строка, начинается с `ssh-ed25519`):

```text
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... vashe.imya@company.com
```

### 1.4. Что прислать администратору

Пришлите **целиком одну строку** из файла `.pub` (или сам файл `.pub` вложением):

- начинается с `ssh-ed25519` (реже `ssh-rsa`);
- вместе с комментарием в конце строки (имя / почта) — так проще понять, чей это ключ.

**Не присылайте:**

- файл без `.pub` (`id_ed25519`, `id_ed25519_neobyte`) — это приватный ключ;
- passphrase;
- скриншот папки `.ssh`.

После того как администратор положит ваш `.pub` на сервер, можно переходить к пункту 2 (файл `config` и проверка `ssh`).

## 2. SSH keepalive (чтобы сессия не обрывалась)

Удалённый сервер и сеть (NAT, VPN, хостер) могут рвать **простаивающее** SSH-соединение. Cursor Remote SSH держит **одно** долгое соединение и не поднимает SSH на каждый запрос; но при обрыве придётся переподключаться.

На **своём Windows** настройте клиентский keepalive.

### 2.1. Файл конфигурации

Путь:

```text
C:\Users\ВАШ_USER\.ssh\config
```

`ВАШ_USER` - имя вашей учётной записи Windows (например `C:\Users\ivan\.ssh\config`).

Если папки `.ssh` нет:

1. Откройте PowerShell.
2. Выполните:

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.ssh"
```

Если файла `config` нет - создайте его (Блокнот или VS Code / Cursor). Расширения у файла быть не должно (имя ровно `config`).

### 2.2. Содержимое (минимум)

Добавьте в файл:

```text
Host *
  ServerAliveInterval 60
  ServerAliveCountMax 10
  TCPKeepAlive yes
```

| Параметр | Зачем |
|----------|--------|
| `ServerAliveInterval 60` | Раз в 60 секунд клиент шлёт серверу «я ещё здесь» |
| `ServerAliveCountMax 10` | До 10 неудачных проверок подряд (~10 минут) до разрыва |
| `TCPKeepAlive yes` | Дополнительный keepalive на уровне TCP |
| `Host *` | Правила для всех SSH-хостов; позже можно сузить до конкретного сервера |

### 2.3. Блок под наш сервер

```text
Host neobyte-dev
  HostName neobyte.twc1.net
  User ИМЯ-ЮЗЕРА-СКАЖЕТ-АДМИНМТРАТОР
  IdentityFile ~/.ssh/id_ed25519
  ServerAliveInterval 60
  ServerAliveCountMax 10
  TCPKeepAlive yes
```

| Поле | Значение |
|------|----------|
| `Host neobyte-dev` | Короткое имя для Cursor / `ssh neobyte-dev` |
| `HostName` | `neobyte.twc1.net` |
| `User` | `ИМЯ-ЮЗЕРА-СКАЖЕТ-АДМИНМТРАТОР` |
| `IdentityFile` | Путь к **приватному** ключу (`id_ed25519` или `id_rsa`) |

Проверка из PowerShell (когда DNS уже отвечает):

```powershell
ssh neobyte-dev
```

## 4. Работа с проектом на сервере

Каталог проекта на сервере (пилот): `/opt/neobyte/project`.

| Можно | Нельзя |
|-------|--------|
| Открывать файлы, искать, читать skills/rules | Сохранять изменения в файлы проекта |
| Пользоваться MCP в Remote-сессии | Править исходники, skills, rules «на сервере» |
| Задавать вопросы ИИ по коду | Свои `git commit` / правки в общем дереве |

Обновление кода на хабе делает администратор. Локальные эксперименты - на своём ПК, не в общей read-only копии на сервере.

## 6. Типовые проблемы

| Симптом | Что проверить |
|---------|----------------|
| SSH обрывается через несколько минут простоя | Пункт 2 (клиентский `config`); сообщить админу - на сервере тоже должен быть keepalive |
| `Permission denied (publickey)` | Ваш `.pub` добавлен на сервер; указан верный `IdentityFile` и `User` |
| Cursor просит переподключить Remote | Обычно после обрыва сети/сна ноутбука; после keepalive должно быть реже |
| `neobyte.twc1.net` не резолвится | Подождать распространения DNS; `nslookup neobyte.twc1.net`; пока ходить по IP |
| Не удаётся сохранить файл / Permission denied при записи | Так задумано: проект на сервере **только чтение**; правки через администратора |
