# Настройка окружения разработчика: Cursor Remote SSH + MCP

**Версия:** 0.5 · **Дата:** 2026-09-11  
**Статус:** рабочая инструкция для нового пользователя  
**Для кого:** разработчики и аналитики 1С (пилот, до 5 человек)  
**Связанные документы:** [описание проекта](tz-cursor-mcp-team.ru.md) · [FAQ для руководства](tz-cursor-mcp-leadership-faq.ru.md) · [спека хаба](spec-ubuntu-hub-pilot.ru.md) · [админ: SSH-пользователи](admin-ssh-users.ru.md)

Документ описывает, что нужно сделать **на своём ПК**, чтобы работать с общим Ubuntu-сервером через Cursor (Remote SSH). Настройки **сервера** здесь не дублируются подробно - их делает администратор хаба.

---

## 0. Что получится в итоге

- На вашем ПК: Cursor (тариф Plus) + расширение Remote - SSH.
- Проект и уже запущенные MCP живут на удалённом Ubuntu.
- Вы подключаетесь по SSH под учёткой разработчика; ИИ в Cursor ходит в облако Cursor, инструменты MCP выполняются на сервере.
- **Запуск Docker, ключи OpenRouter / LICENSE_KEY и файлы `.env` - зона администратора.** Разработчик их не создаёт и не читает.
- **Файлы проекта на сервере только для чтения:** исходники, skills, rules и прочее содержимое репозитория разработчик **не** правит. Обновляет дерево администратор.

## 1. Предусловия

| Что | Кто выдаёт / откуда |
|-----|---------------------|
| Подписка Cursor Plus ($8/мес) | Каждый покупает сам на cursor.com |
| SSH-доступ к серверу (логин разработчика + ваш публичный ключ на сервере) | Администратор хаба |
| Hostname сервера | `neobyte.twc1.net` (технический домен Timeweb; DNS может распространяться несколько минут/часов после добавления) |
| (позже) список MCP в Cursor (уже поднятых админом) | Администратор хаба |

Пока сервер временный (Timeweb). После согласования основного сервера обновятся только адрес и, при необходимости, логин - этот документ поправим.

Учётка разработчика (личный Linux-логин, например `NikitaN`; переходный общий `neobyte` больше не выдаём новым людям):
- открыть проект в Cursor Remote SSH;
- пользоваться MCP;
- **не** сохранять правки в файлы проекта (исходники, `.cursor/skills`, `.cursor/rules` и т.д.);
- **не** читать секреты и **не** управлять Docker.

Вход на сервер **только по SSH-ключу** (`ed25519`). Пароля у учётки нет.

Если Cursor пишет, что файл нельзя сохранить - так и задумано. Нужные изменения в репозитории делает администратор хаба.

Проверка, что DNS уже отвечает:

```powershell
nslookup neobyte.twc1.net
```

Должен вернуться IP сервера из панели Timeweb. Пока не отвечает - подождите и повторите; по IP подключаться можно сразу.

## 1.1. Сгенерировать ключ ed25519 на Windows

Это делается **один раз на своём ПК**. Приватный ключ никому не отправляйте (ни в чат, ни админу). Админу нужна только строка из файла `*.pub`.

1. Откройте PowerShell.
2. Выполните:

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.ssh" | Out-Null
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519" -C "$env:USERNAME@windows"
```

3. На вопрос passphrase можно задать пароль на ключ (рекомендуется) или оставить пустым (Enter).
4. Покажите **публичный** ключ и отправьте админу **целиком одну строку**:

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

Строка начинается с `ssh-ed25519`. Файл `id_ed25519` без `.pub` — приватный, его не копируйте.

Админ кладёт `.pub` в `authorized_keys` вашей учётки (см. [admin-ssh-users.ru.md](admin-ssh-users.ru.md) §2). Пока ключ не добавлен, `ssh` ответит `Permission denied (publickey)`.

Если ключ `id_ed25519` уже есть — новый не создавайте; отправьте существующий `.pub`.

## 2. SSH keepalive (чтобы сессия не обрывалась)

Удалённый сервер и сеть (NAT, VPN, хостер) могут рвать **простаивающее** SSH-соединение. Cursor Remote SSH держит **одно** долгое соединение и не поднимает SSH на каждый запрос; но при обрыве придётся переподключаться.

На **своём Windows** настройте клиентский keepalive.

### 2.1. Файл конфигурации

Путь:

```text
C:\Users\ВАШ_USER\.ssh\config
```

`ВАШ_USER` - имя вашей учётной записи Windows (например `C:\Users\ivan\.ssh\config`).

Если папки `.ssh` нет:

1. Откройте PowerShell.
2. Выполните:

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.ssh"
```

Если файла `config` нет - создайте его (Блокнот или VS Code / Cursor). Расширения у файла быть не должно (имя ровно `config`).

### 2.2. Содержимое (минимум)

Добавьте в файл:

```text
Host *
  ServerAliveInterval 60
  ServerAliveCountMax 10
  TCPKeepAlive yes
```

| Параметр | Зачем |
|----------|--------|
| `ServerAliveInterval 60` | Раз в 60 секунд клиент шлёт серверу «я ещё здесь» |
| `ServerAliveCountMax 10` | До 10 неудачных проверок подряд (~10 минут) до разрыва |
| `TCPKeepAlive yes` | Дополнительный keepalive на уровне TCP |
| `Host *` | Правила для всех SSH-хостов; позже можно сузить до конкретного сервера |

### 2.3. Блок под наш сервер

```text
Host neobyte-dev
  HostName neobyte.twc1.net
  User NikitaN
  IdentityFile ~/.ssh/id_ed25519
  ServerAliveInterval 60
  ServerAliveCountMax 10
  TCPKeepAlive yes
```

Подставьте в `User` **свой** Linux-логин, который выдал администратор (пример: `NikitaN`). Регистр важен.

| Поле | Значение |
|------|----------|
| `Host neobyte-dev` | Короткое имя для Cursor / `ssh neobyte-dev` |
| `HostName` | `neobyte.twc1.net` |
| `User` | ваш Linux-логин на хабе |
| `IdentityFile` | Путь к **приватному** ключу (`id_ed25519`) |

Проверка из PowerShell (когда DNS уже отвечает и админ добавил ваш `.pub`):

```powershell
ssh neobyte-dev
```

Должен пустить **без пароля** (если на ключ задали passphrase — спросит её, это нормально). Выйдите: `exit`.

Временно, пока DNS не разошёлся:

```powershell
ssh NikitaN@ВАШ_IP
```

## 3. Установка Cursor на Windows и Remote SSH

Нужен тариф **Cursor Plus** ($8/мес; каждый покупает сам на [cursor.com/pricing](https://cursor.com/pricing)).

### 3.1. Поставить Cursor

1. Скачайте установщик Windows: [https://cursor.com/download](https://cursor.com/download) — пункт **Windows** (x64; ARM64 только для Snapdragon/ARM-ноутбуков).
2. Запустите `.exe`, согласитесь с установкой.
3. Откройте Cursor → войдите в свой аккаунт с активной подпиской Plus.

Клиент OpenSSH в Windows 10/11 обычно уже есть (`ssh` в PowerShell). Если команд `ssh` / `ssh-keygen` нет: **Параметры → Приложения → Дополнительные компоненты → OpenSSH Client**.

### 3.2. Расширение Remote SSH

1. В Cursor откройте Extensions (`Ctrl+Shift+X`).
2. Найдите **Remote - SSH** от Anysphere: в поиске `@id:anysphere.remote-ssh`.
3. Установите его.
4. Если стоит Microsoft **Remote - SSH** (`ms-vscode-remote.remote-ssh`) — удалите: два расширения конфликтуют.

### 3.3. Подключиться к хабу

1. `F1` (или `Ctrl+Shift+P`) → команда **`Remote-SSH: Connect to Host...`**.
2. Выберите **`neobyte-dev`** (имя из вашего `~\.ssh\config`).
3. Если спросят ОС сервера — **Linux**.
4. Откроется новое окно Cursor. Внизу слева обычно видно `SSH: neobyte-dev`.
5. Первый заход ставит remote-server в ваш home на Ubuntu (`/home/<логин>/.cursor-server`) — подождите 1–2 минуты.

Проверка в терминале remote-окна:

```bash
whoami
pwd
ls /opt/neobyte/project
```

Ожидаемо: `whoami` = ваш логин; каталог `project` читается.

### 3.4. Открыть проект

1. **File → Open Folder...**
2. Путь: `/opt/neobyte/project`
3. Confirm / OK.

Дальше работаете в этом окне: чат с ИИ, MCP, поиск по конфигурации. Сохранять файлы проекта нельзя — это read-only (см. §4).

## 4. Работа с проектом на сервере

Каталог проекта на сервере (пилот): `/opt/neobyte/project`.

| Можно | Нельзя |
|-------|--------|
| Открывать файлы, искать, читать skills/rules | Сохранять изменения в файлы проекта |
| Пользоваться MCP в Remote-сессии | Править исходники, skills, rules «на сервере» |
| Задавать вопросы ИИ по коду | Свои `git commit` / правки в общем дереве |
| Класть файлы для ИИ в свой `/home/<логин>/` (см. ниже) | |

Обновление кода на хабе делает администратор. Локальные эксперименты - на своём ПК, не в общей read-only копии на сервере.

**Файлы для анализа ИИ:** пишите в свой home, например `/home/<логин>/inbox/`. В Cursor: *File → Add Folder to Workspace* → этот каталог, затем `@inbox/...` в чате. Либо Attach файла с локального ПК (на сервер класть не обязательно). Чужой `/home` коллегам не виден.

*Детали путей выгрузок и MCP будут дополнены.*

## 6. Типовые проблемы

| Симптом | Что проверить |
|---------|----------------|
| SSH обрывается через несколько минут простоя | Пункт 2 (клиентский `config`); сообщить админу - на сервере тоже должен быть keepalive |
| `Permission denied (publickey)` | Ваш `.pub` добавлен на сервер; указан верный `IdentityFile` и `User` |
| Cursor просит переподключить Remote | Обычно после обрыва сети/сна ноутбука; после keepalive должно быть реже |
| `neobyte.twc1.net` не резолвится | Подождать распространения DNS; `nslookup neobyte.twc1.net`; пока ходить по IP |
| Microsoft Remote SSH / конфликт расширений | Удалить `ms-vscode-remote.remote-ssh`, оставить `@id:anysphere.remote-ssh` |
| `ssh` / `ssh-keygen` не найдены в PowerShell | Включить OpenSSH Client в дополнительных компонентах Windows |
