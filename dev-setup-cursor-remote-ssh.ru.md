# Настройка окружения разработчика: Cursor Remote SSH + MCP

**Версия:** 0.6 · **Дата:** 2026-09-11  
**Статус:** черновик (дополняется по ходу настройки сервера)  
**Для кого:** разработчики и аналитики 1С (пилот, до 5 человек)  
**ОС:** Windows и macOS  

Документ описывает, что нужно сделать **на своём компьютере**, чтобы работать с общим Ubuntu-сервером через Cursor (Remote SSH). Настройки **сервера** здесь не дублируются подробно — их делает администратор хаба.

Где команды или пути различаются, шаги даны отдельно для **Windows** и **macOS**. Содержимое `~/.ssh/config` и то, что прислать администратору, одинаково.

---

## 1. Новый SSH-ключ: создать и прислать публичную часть

Без вашего публичного ключа администратор не сможет выдать доступ на сервер. Сгенерируйте **новую** пару ключей на своём ПК, затем пришлите **только публичную** часть.

**Приватный** ключ никуда не отправляйте: он остаётся только у вас.

### 1.1. Создать ключ

#### Windows

1. Откройте **PowerShell**.
2. Сгенерируйте ключ типа Ed25519 (папку `.ssh` команда создаст сама, если её ещё нет):

```powershell
ssh-keygen -t ed25519 -C "vashe.imya@company.com"
```

3. На вопросы `ssh-keygen`:
   - **путь к файлу** — Enter, если подходит значение по умолчанию (`C:\Users\ВАШ_USER\.ssh\id_ed25519`);
   - **passphrase** — можно задать или оставить пустой (два раза Enter).

Если команда спрашивает **перезаписать** уже существующий `id_ed25519` — отвечайте **n**. Задайте другое имя:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519_neobyte" -C "vashe.imya@company.com"
```

#### macOS

1. Откройте **Терминал** (Terminal.app) или iTerm.
2. Сгенерируйте ключ типа Ed25519 (папку `~/.ssh` команда создаст сама, если её ещё нет):

```bash
ssh-keygen -t ed25519 -C "vashe.imya@company.com"
```

3. На вопросы `ssh-keygen`:
   - **путь к файлу** — Enter, если подходит значение по умолчанию (`/Users/ВАШ_USER/.ssh/id_ed25519`);
   - **passphrase** — можно задать или оставить пустой (два раза Enter).

Если команда спрашивает **перезаписать** уже существующий `id_ed25519` — отвечайте **n**. Задайте другое имя:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_neobyte -C "vashe.imya@company.com"
```

**Рекомендуется на macOS** (чтобы passphrase хранилась в связке ключей и Cursor/SSH не спрашивали её каждый раз):

```bash
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```

Если ключ назвали иначе — подставьте свой путь к приватному файлу.

В `-C` укажите своё имя или рабочую почту — так ключ проще узнать в списке.  
Если использовали другое имя файла — в пункте 2 в `IdentityFile` укажите его (`~/.ssh/id_ed25519_neobyte`), а не `id_ed25519`.

### 1.2. Что получилось на диске

| Файл | Это | Куда |
|------|-----|------|
| `id_ed25519` (без `.pub`) | **Приватный** ключ | Только ваш ПК. Никому не присылать, не копировать в чат, не класть в git |
| `id_ed25519.pub` | **Публичный** ключ | Этот файл (или его содержимое) прислать администратору |

Путь по умолчанию:

| ОС | Папка |
|----|--------|
| Windows | `C:\Users\ВАШ_USER\.ssh\` |
| macOS | `/Users/ВАШ_USER/.ssh/` (то же, что `~/.ssh/`) |

### 1.3. Показать публичный ключ

#### Windows (PowerShell)

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

Если ключ назвали иначе:

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519_neobyte.pub"
```

#### macOS (Терминал)

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопировать сразу в буфер обмена:

```bash
pbcopy < ~/.ssh/id_ed25519.pub
```

Если ключ назвали иначе — подставьте имя файла, например `~/.ssh/id_ed25519_neobyte.pub`.

Строка выглядит так (одна строка, начинается с `ssh-ed25519`):

```text
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... vashe.imya@company.com
```

### 1.4. Что прислать администратору

Пришлите **целиком одну строку** из файла `.pub` (или сам файл `.pub` вложением):

- начинается с `ssh-ed25519` (реже `ssh-rsa`);
- вместе с комментарием в конце строки (имя / почта) — так проще понять, чей это ключ.

**Не присылайте:**

- файл без `.pub` (`id_ed25519`, `id_ed25519_neobyte`) — это приватный ключ;
- passphrase;
- скриншот папки `.ssh`.

После того как администратор положит ваш `.pub` на сервер, можно переходить к пункту 2 (файл `config` и проверка `ssh`).

## 2. SSH keepalive (чтобы сессия не обрывалась)

Удалённый сервер и сеть (NAT, VPN, хостер) могут рвать **простаивающее** SSH-соединение. Cursor Remote SSH держит **одно** долгое соединение и не поднимает SSH на каждый запрос; но при обрыве придётся переподключаться.

Настройте клиентский keepalive на **своём** компьютере (Windows или macOS).

### 2.1. Файл конфигурации

| ОС | Путь к файлу |
|----|----------------|
| Windows | `C:\Users\ВАШ_USER\.ssh\config` |
| macOS | `/Users/ВАШ_USER/.ssh/config` (или `~/.ssh/config`) |

`ВАШ_USER` — имя вашей учётной записи (например `ivan` → Windows: `C:\Users\ivan\.ssh\config`, macOS: `/Users/ivan/.ssh/config`).

После пункта 1 папка `.ssh` уже есть. Если файла `config` нет — создайте его:

- **Windows:** Блокнот, VS Code или Cursor; имя ровно `config`, без расширения `.txt`.
- **macOS:** в Терминале, например:

```bash
nano ~/.ssh/config
```

или откройте в Cursor / TextEdit. Имя файла ровно `config`.

На **macOS** после сохранения задайте права (иначе `ssh` может игнорировать `config`):

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/config
```

### 2.2. Содержимое (минимум)

Добавьте в файл (одинаково на Windows и macOS):

```text
Host *
  ServerAliveInterval 60
  ServerAliveCountMax 10
  TCPKeepAlive yes
```

| Параметр | Зачем |
|----------|--------|
| `ServerAliveInterval 60` | Раз в 60 секунд клиент шлёт серверу «я ещё здесь» |
| `ServerAliveCountMax 10` | До 10 неудачных проверок подряд (~10 минут) до разрыва |
| `TCPKeepAlive yes` | Дополнительный keepalive на уровне TCP |
| `Host *` | Правила для всех SSH-хостов; позже можно сузить до конкретного сервера |

### 2.3. Блок под наш сервер

#### Windows

```text
Host neobyte-dev
  HostName neobyte.twc1.net
  User ИМЯ-ЮЗЕРА-СКАЖЕТ-АДМИНИСТРАТОР
  IdentityFile ~/.ssh/id_ed25519
  ServerAliveInterval 60
  ServerAliveCountMax 10
  TCPKeepAlive yes
```

#### macOS

То же, плюс строки для связки ключей (удобно, если задавали passphrase):

```text
Host neobyte-dev
  HostName neobyte.twc1.net
  User ИМЯ-ЮЗЕРА-СКАЖЕТ-АДМИНИСТРАТОР
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  AddKeysToAgent yes
  UseKeychain yes
  ServerAliveInterval 60
  ServerAliveCountMax 10
  TCPKeepAlive yes
```

| Поле | Значение |
|------|----------|
| `Host neobyte-dev` | Короткое имя для Cursor / `ssh neobyte-dev` |
| `HostName` | `neobyte.twc1.net` |
| `User` | логин, который скажет администратор |
| `IdentityFile` | путь к **приватному** ключу (`id_ed25519` или ваше имя файла) |
| `UseKeychain` / `AddKeysToAgent` | только macOS; хранение ключа в Keychain |

Проверка:

**Windows (PowerShell)** или **macOS (Терминал)** — одна и та же команда:

```text
ssh neobyte-dev
```

## 3. Cursor и Remote SSH

*Раздел будет дополнен подробно. Кратко для обеих ОС:*

1. Установите Cursor (тариф Teams) с [cursor.com](https://cursor.com) — есть сборки для Windows и macOS.
2. В Cursor установите расширение **Remote - SSH** (`anysphere.remote-ssh`), если его ещё нет.
3. Подключение: Command Palette → **Remote-SSH: Connect to Host…** → выберите `neobyte-dev` (из вашего `~/.ssh/config`).
4. Откройте папку проекта на сервере: `/opt/neobyte/project`.

На macOS при первом подключении система может запросить доступ к связке ключей — разрешите.

## 4. Работа с проектом на сервере

Каталог проекта на сервере (пилот): `/opt/neobyte/project`.

Правила одинаковы для Windows и macOS — отличается только локальный клиент Cursor.

| Можно | Нельзя |
|-------|--------|
| Открывать файлы, искать, читать skills/rules | Сохранять изменения в файлы проекта |
| Пользоваться MCP в Remote-сессии | Править исходники, skills, rules «на сервере» |
| Задавать вопросы ИИ по коду | Свои `git commit` / правки в общем дереве |

Обновление кода на хабе делает администратор. Локальные эксперименты — на своём ПК, не в общей read-only копии на сервере.

*Детали путей выгрузок и MCP будут дополнены.*

## 6. Типовые проблемы

| Симптом | Что проверить |
|---------|----------------|
| SSH обрывается через несколько минут простоя | Пункт 2 (клиентский `config`); сообщить админу — на сервере тоже должен быть keepalive |
| `Permission denied (publickey)` | Ваш `.pub` добавлен на сервер; верный `IdentityFile` и `User`; на macOS — `ssh-add --apple-use-keychain …` и `UseKeychain yes` |
| macOS: `Bad owner or permissions on …/.ssh/config` | `chmod 700 ~/.ssh` и `chmod 600 ~/.ssh/config` |
| Cursor просит переподключить Remote | Обычно после обрыва сети/сна ноутбука; после keepalive должно быть реже |
| Не удаётся сохранить файл / Permission denied при записи | Так задумано: проект на сервере **только чтение**; правки через администратора |
