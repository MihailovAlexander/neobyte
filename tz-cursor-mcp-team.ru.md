## 3. Как это устроено (без техники)

Представьте три слоя:

```
Люди
  • IT открывает Cursor на своём компьютере и видит код на общем сервере (только чтение)
  • Пользователи открывают сайт-чат и задают вопросы по-русски

Общий сервер компании («хаб»)
  • Хранит выгрузки конфигураций
  • Строит по ним быстрый поиск («память» системы)
  • Там же — мониторинг, оповещения для IT, веб-чат

Отдельно (по желанию)
  • Сервер тестовых баз 1С — только тесты, не боевые данные клиентов
```

**Важно:**
- Боевые базы с клиентскими данными к этому контуру **не** подключаем.
- Предложение ITG «виртуалка за $960/мес без прямой связи с нашими серверами» **невыгодно** — см. §6.
- Рекомендуем обычный выделенный сервер (ориентир Hetzner ~€259/мес) с двумя дисками: один под систему и файлы, второй под «память» поиска (чтобы ночное обновление не мешало работе).

---

## 4. Обновление «памяти» (поиска)

После изменений в конфигурациях нужно обновить поиск.

| Когда | Что делаем |
|-------|------------|
| Ночь | Обновляем то, что изменилось |
| Выходные | Полная перепроверка всех 15 при необходимости |
| По команде админа | Срочно одну конфигурацию |

Цель: поиск не старше **7 дней**. Если отстал — оповещение команде IT.

Два диска нужны не «чтобы было много терабайт», а чтобы тяжёлая ночная работа шла на отдельном диске. По объёму достаточно примерно **0,5 ТБ + 1 ТБ**; у дешёвого сервера Hetzner диски больше — это запас, не обязательная норма.

---

## 5. Наблюдение за работой

На том же сервере — простые экраны состояния и оповещения в корпоративный мессенджер (бесплатная версия Mattermost хватит для IT).

Что важно видеть:
- поиск «живой» или упал;
- поиск устарел больше чем на неделю;
- мало места на диске;
- чат для пользователей: сколько спрашивали (журнал вопросов).

## 6. Сервер: Hetzner или ITG

| | Hetzner (рекомендуем) | ITG (КП от 26.08.2026) |
|-|----------------------|-------------------------|
| Цена в месяц | около **€259** | **$960** |
| Тип | Свой выделенный сервер | Внешняя виртуальная машина |
| Прямая сеть к нашим текущим серверам | Нет (как у любой внешней площадки) | **Нет** (подтвердила ITG) |
| Диски под ночной поиск | Два отдельных быстрых диска | Один общий диск в облаке |

**Вывод для руководства:** при цене в 3 раза выше и без сетевого преимущества у ITG **почти нет плюсов**. Для проекта лучше выделенный сервер уровня Hetzner AX102 (или аналог с похожими характеристиками).

Нужно примерно: 16–24 ядра процессора, 128 ГБ памяти, два раздела диска, без видеокарты на старте.

## 7. Безопасность (кратко)

Подробно — в [оценке проекта](tz-cursor-mcp-governance-assessment.ru.md).

| Тема | Как делаем |
|------|------------|
| Доступ IT | Только через корпоративную сеть; на сервере — только чтение файлов |
| Увольнение | Отключить сеть → убрать доступ к серверу → убрать компенсацию Cursor |
| Боевые данные | Не индексируем, не подключаем |
| Облако ИИ | Вопросы в Cursor и в чате могут уходить во внешний ИИ — запрещаем пароли и данные клиентов в тексте вопросов; включаем режим приватности |
| Веб-чат | Только консультации; журнал всех диалогов; без выгрузки списков клиентов |

---

## 8. Веб-чат для пользователей (до 50 человек)

Входит в **текущее** утверждение и бюджет.

Пользователь:
1. Входит под своей учёткой.  
2. Выбирает конфигурацию из списка.  
3. Спрашивает обычным языком.  
4. Получает объяснение и ссылки на объекты системы (без возможности что-то сломать в боевой базе).

Рекомендуем открытую программу **Open WebUI** на нашем сервере.  
Мессенджер Telegram для этого **не** рекомендуем (данные уходят наружу).

Ответы чата строит отдельный ИИ-сервис (не подписка Cursor). Оплата — с момента включения чата.

## 10. План работ

| Шаг | Срок | Результат |
|-----|------|-----------|
| 1. Сервер и пилот | 1–3 недели | Несколько конфигураций, несколько человек IT |
| 2. Все IT | 4–8 недель | 15 конфигураций, 15 человек, оповещения |
| 3. Устойчивая работа | до 3 месяцев | Контроль «поиск не старше недели»; при необходимости — тестовые базы |
| 4. Чат | месяцы 3–6 | Пилот 10–15 пользователей → проверка безопасности → до 50 |

После шага 1 можно остановиться, если польза не подтвердилась.

## 11. Риски

| Риск | Как снижаем |
|------|-------------|
| Ночное обновление поиска долгое | Отдельный диск; обновлять несколько конфигураций параллельно |
| Дорогой сервер «по привычке» у ITG | Берём рыночный выделенный сервер (~€259), не $960 |
| ИИ ответит лишнее в чате | Нет боевых баз; фильтры; журнал; проверка перед «всем 50» |
| Лицензии поиска дороже ожидания | Сначала пилот на нескольких конфигурациях; докупаем по факту |
